## 一句话
**AMX（Ambiorix）是 prplOS 的核心框架：用 C 实现了一套「组件容器 + 总线抽象 + 数据模型」。**

对 Java 背景的人，最直观的类比是：**它有点像 C 版的 Spring 容器**——管组件、管生命周期、管依赖。但它又**不只是 DI**，它还管"总线"和"对象树"。这一篇先把整体图讲清楚。

## 为什么需要它
嵌入式世界的"总线"是分裂的：

- **ubus**（OpenWrt）
- **D-Bus**（RDK-B / 桌面）
- 以及各种私有总线

结果是：**同一个业务组件，换个平台就要重写一遍接口。**

AMX 的目标很明确：

> **做一层统一的 C API，屏蔽底层总线；让组件能在不同总线/平台之间复用。**

这就是它存在的理由——不是又一个总线，而是**总线的抽象层**。

## 分层图
```
        客户端 / 应用（amx-cli · ba-cli · Web UI）
                        │
                  ┌─────▼─────┐
                  │  libamxb  │  总线抽象（ubus / D-Bus / 私有）
                  └─────┬─────┘
                        │
        ┌───────────────▼───────────────┐
        │  libamxd  数据模型（对象树）   │◄── libamxo  ODL 装配/解析
        │  Object / Parameter / Function│
        └───────────────┬───────────────┘
                        │
                  ┌─────▼─────┐
                  │  libamxc  │  基础容器（List / Hash / Variant）
                  └───────────┘

        libamxrt = 运行时容器：组件生命周期 init → start → stop
```

## 「四件套」各管什么

**1. `libamxc` —— 基础容器**
C 没有标准容器库。`libamxc` 提供链表、哈希、动态数组、变体（Variant）等。
**一句话：AMX 的"积木"。**

**2. `libamxd` —— 数据模型（对象树）**
用"对象 / 参数 / 函数"描述一个组件能做什么、有什么状态。比如设备信息、WAN 状态，最终都落成一棵可寻址的对象树。
**一句话：AMX 的"Bean 与属性"。**

**3. `libamxb` —— 总线抽象**
把底层总线（ubus / D-Bus）屏蔽掉，统一成一套调用/查询接口。
**一句话：AMX 的"依赖查找与调用"。**

**4. `libamxo` —— 装配（ODL）**
ODL（Object Definition Language）用来**描述并加载对象树**：组件有哪些对象、参数、函数。
**一句话：AMX 的"配置/装配"。**

再加上 **`libamxrt`（运行时）**：负责组件的加载与生命周期（init / start / stop）。
**一句话：AMX 的"运行时容器"。**

## 和 Spring 对照
| Spring | AMX | 作用 |
|---|---|---|
| Bean 容器 / IoC | `libamxrt` + `libamxd` | 管理组件与对象生命周期 |
| Bean / 属性 | Object / Parameter（`libamxd`） | 数据模型 |
| `@Autowired` / 查找 | `libamxb` | 组件解耦、总线查找 |
| XML / 注解装配 | `libamxo` 的 **ODL** | 描述并加载对象树 |
| 基础集合 | `libamxc` | C 里的容器 |

**但要说清差异**：Spring 是**依赖注入框架**；AMX 是**总线抽象 + 数据模型 + 组件框架**。用"容器"做类比是好用的钩子，但**别把它当成纯 DI**。

## 一条最小链路（概念）
```
ODL 描述对象树
   → libamxo 解析、装进 libamxd
   → 组件注册到 libamxb
   → 客户端通过总线 查询/调用 对象
```
你平时用 `ba-cli` 查节点，走的就是这条链路的最后一公里。

## 边界
- AMX 管的是**组件与接口**，不管业务；
- 它的价值在"**换总线不改业务代码**"；
- 它不是万能框架，**数据模型设计得好不好，仍取决于写组件的人**。
